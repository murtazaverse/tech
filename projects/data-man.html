01 / Context

The problem

Asking a question about a database can require understanding its schema, writing SQL, and preparing the result for analysis. Data-Man explores how natural-language interaction can connect these steps.

02 / Approach

How the pieces connect

An agentic workflow coordinates SQL analysis and ETL agents. Schema-aware RAG retrieves relevant table and column context for SQL generation. TypeSafeAI JEV supports tool-call selection, guardrail enforcement, and evaluation of routing, execution, and response quality.

04 / My work

My engineering contributions

  • Engineered a workflow coordinating SQL analysis and ETL agents for natural-language database queries and transformation requests.
  • Implemented schema-aware RAG to retrieve relevant table and column context for SQL generation.
  • Integrated TypeSafeAI JEV for tool-call selection, guardrails, and evaluation of routing decisions, tool execution, and response quality.

05 / Engineering considerations

The decisions around the system

These are the tradeoffs this type of system needs to account for.

  • Schema context helps ground SQL generation, while retrieval relevance remains an important evaluation target.
  • Coordinating specialized tools introduces routing decisions that need guardrails and evaluation alongside answer quality.

06 / Outcome & status

What came out of it

An implemented natural-language workflow for PostgreSQL queries and requested data transformations. No quantitative benchmark is supplied.
